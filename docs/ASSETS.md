# Assets and provenance

Every file under `godot/assets/` has a row in `tools/art/provenance.toml` (checked by
`tools/ci.sh`). Fields: path, kind, source (generated | sourced | hand), generator or URL,
licence, retrieved date, notes. Generated assets are regenerable from `tools/art/` and the
master palette `tools/art/palette.py`.

Rehearsal status: this CI source candidate includes recipes for 113 independently generated fallback sprites
(105 large and eight small), recorded in `tools/art/fallback/manifest.json`. Their provenance is
tracked textual templates plus newly authored geometry, with no source-image input. The generated outputs are
unreviewed, not the unavailable replacement packet, and not selected for publication. No rights
clearance is asserted. Existing [asset notices](../LICENSE-ASSETS) remain for review; the proposed
CC BY-SA grant must not be treated as clearance for these test inputs. Code remains under
[GPL-3.0-or-later](../LICENSE).

`python3 tools/art/fallback/generate.py` reproduces the pinned fallback bytes. The old sheet
pipeline is disabled and excluded from the rehearsal export. `items.py` preserves protected
slots; provenance generation requires the exact fallback policy and records unresolved rights.
Missing or changed policy fails closed. Do not use this source snapshot as release authorization.

The fallback has recognizable basic forms but similar and sometimes dark material variants.
Actual default-layer alignment, visual acceptance and rights review remain outstanding.

Policy: assets are chosen by quality against docs/ART_BIBLE.md. Licences accepted: CC0,
OFL, MIT, CC-BY (with an attribution file `godot/assets/ATTRIBUTION.md`, not needed while no
third-party asset ships), and commercial-ok packs with recorded terms. A packed asset must also
be free to redistribute under CC BY-SA 4.0 or it does not ship. Nothing without a licence record ships.

Rendered PNG/Ogg payloads are not committed. The table below describes declared generator
outputs; it is not a list of shipped media or evidence of rights clearance.

## Production asset acceptance

An art idea or renderer mockup belongs in an issue, review note or design document. A production
art PR must include real files under `godot/assets/` or the runtime code that consumes them, plus
the generator or integration needed to keep them in use. It must also include provenance rows,
palette/dimension validation, a focused guard where the family has structural requirements, and
before/after contact-sheet or integrated-game evidence. The PR description must name what is
actually implemented and what remains a future direction. Reference images are never silently
treated as shippable project art.
